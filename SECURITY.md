# Política de segurança

## Versões mantidas

Este é um laboratório de projetos pessoais. A branch `main` é a única linha de desenvolvimento mantida ativamente.

Os projetos são páginas estáticas e não devem armazenar senhas, tokens, chaves de API ou outros segredos no código-fonte.

## Reportando uma vulnerabilidade

Não publique detalhes de uma vulnerabilidade em uma issue pública.

Envie um relatório privado pelo recurso **Report a vulnerability** da aba **Security** do repositório. Se esse recurso não estiver disponível, entre em contato com o mantenedor por um canal privado disponível em [ronanrodrigo.dev](https://ronanrodrigo.dev).

Inclua, quando possível:

* Projeto e arquivo afetado.
* Descrição do problema e impacto provável.
* Passos para reproduzir a falha.
* Evidências ou uma demonstração mínima, sem dados sensíveis.
* Sugestão de correção, se houver.

Não inclua credenciais reais no relatório. Caso uma chave tenha sido exposta, revogue-a imediatamente e informe apenas os dados necessários para identificar o incidente.

O recebimento será confirmado assim que possível. O prazo de correção depende da gravidade, da facilidade de reprodução e do impacto sobre os usuários.
